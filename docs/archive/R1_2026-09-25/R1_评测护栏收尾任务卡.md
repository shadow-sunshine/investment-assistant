## 1. 目标

收尾 R0/R1 双语检索评测护栏，确保：

1. 所有目标页相关性指标使用一致判定，不能把不同 ticker 的同页码当作命中。
2. R1 候选池实验只能与被冻结的 R0 样本集对比；样本集发生变化时，必须在索引/检索前阻断。
3. 结果复渲染时也要验证样本集身份；不能用新样本重写旧实验报告。

本任务不做检索算法优化，不切换线上检索路径。

## 2. 开始前必须做

1. 确认当前目录和 Git 根目录均为本仓库根目录。
2. 输出 `git status --short --untracked-files=all`、`git diff --stat`。
3. 阅读 `.codebuddy/CODEBUDDY.md`、本任务卡、目标模块和相关测试。
4. 将开始时已存在的改动/未跟踪文件视为用户已有内容；不得覆盖、恢复、清理或顺手整理。
5. 若发现任务卡与当前代码状态不一致，先报告差异；只针对本任务仍未满足的验收项实施，不重复重做已完成项。

## 4. 必须完成的实现

### A. 统一目标来源判定

1. 检查 `bilingual_eval.py` 和 `candidate_pool_eval.py` 中以下字段的计算：
   - `page_hit_at_k`
   - `keyword_verified_hit_at_k`
   - `top_result_is_relevant`
   - `unscoped_page_hit_at_k`
2. 统一调用目标来源判定函数；必须校验来源的 ticker（或与样本目标资料一致的文件身份）以及 gold page。
3. `top_result_is_relevant` 不得只比较页码；关键词核验必须基于已判定为目标来源的证据。
4. 如果 R0/R1 使用不同结果结构，复用共同 helper 或保证逻辑完全一致并有测试覆盖；不要为减少重复而引入不必要的大重构。

### B. 固定 R0 样本集身份

1. 先检查 Git 历史，确认 R0 样本首次冻结的提交和文件：优先核实 `c0f5782` 中的 `data/bilingual_eval_set.json`。不要凭文件名或记忆假定它是基线。
2. 以样本文件原始字节计算 SHA256，并与冻结提交中的原始字节比较。记录基线 SHA 和其来源（提交、路径）。如果该提交/文件无法验证，停止并报告，不得自行选择当前文件作为“历史基线”。
3. 将已核实的冻结 SHA 以可审阅的方式固定在代码常量或版本化基线元数据中；说明只有显式创建新评测基线时才可更新。
4. R0/R1 新生成的结果应记录 `eval_set_sha256`。R1 还应记录它所对照的冻结 R0 SHA。
5. R1 接受 `--eval-set` 时，若 SHA 不等于冻结基线，必须在建索引和调用检索前返回明确 `BLOCKED` 状态；不能只记录 drift 后继续跑。
6. `render_from_result()` 在重渲染前必须校验输入样本 SHA 与结果中记录的 SHA 一致；不一致时不得输出看似正常的可比报告，应明确阻断。
7. 对旧结果缺少 SHA 的情况要 fail-closed：不得静默把当前文件 SHA 补写成旧实验的 SHA。若需迁移旧结果，必须通过已有记录证明其样本身份并清楚标注迁移依据；无法证明则保留旧结果、不宣称可比。

## 5. 必须先写的回归测试

先新增/调整测试，再实现代码。至少覆盖：

1. 正确 ticker + gold page 才是命中。
2. 错误 ticker + 相同 page 不是命中。
3. 正确 ticker + 非 gold page 不是命中。
4. R0 与 R1 的 `top_result_is_relevant` 均走统一判定；用错误 ticker 同页码作为反例。
5. R1 使用冻结 SHA 的评测集可以继续；内容变化导致 SHA 不同则 `BLOCKED`，且 `run_mode`/建索引入口未被调用。
6. `render_from_result()` 遇到 SHA 不一致或旧结果无 SHA 时 fail-closed，不生成正常报告。
7. 资料 SHA drift/missing 的既有 fail-closed 行为继续成立。

测试应使用临时目录、fake RAG 或 monkeypatch；不访问网络、不重建真实 Chroma 索引、不依赖昂贵模型加载。

除非代码或结果格式变化确实要求重新产生检索结果，否则不要运行耗时的全量 R0/R1 检索实验。不得为了让测试通过而修改 gold page、删样本或放宽断言。

## 7. 完成标准

全部满足才可报告任务完成：

- 目标来源判断在 R0/R1 中统一且测试覆盖反例；
- 冻结 R0 样本 SHA 有 Git 历史证据；
- R1 的错误样本 SHA 在任何建索引/检索之前阻断；
- 报告复渲染在身份不匹配或缺少身份信息时 fail-closed；
- 针对性测试、全量测试和 `git diff --check` 的结果如实报告；
- 冻结区未改、用户原有改动未被覆盖；
- 最终 `git status` 已再次输出；无暂存或提交操作。
