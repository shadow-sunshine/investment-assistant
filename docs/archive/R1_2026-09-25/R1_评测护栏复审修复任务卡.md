## 2. 本轮审阅发现

### R1-F1（P1）：R1 mismatch BLOCKED 结果无法重渲染

`candidate_pool_eval.py` 中 `eval_set_mismatch` 分支没有 `material_verification`，但 `render_from_result()` 对所有 `status=blocked` 的 payload 都直接读取该字段并调用资料漂移报告渲染。实测可能抛 `KeyError`，而不是稳定生成 BLOCKED 报告。

### R1-F2（P2）：R1 复渲染未重新校验冻结基线

目前若只检查 `stored_sha == current_sha`，只能证明结果和当前文件一致，不能证明两者等于冻结 R0 SHA。必须校验结果 SHA、当前样本 SHA、冻结基线 SHA 三者一致；已有 `matches_frozen_baseline=False` 时也不得生成正常报告。

### R1-F3（P2）：当前 R1 JSON 缺少最新基线字段

当前 `data/evaluations/candidate_pool_sensitivity.json` 有 `eval_set_sha256` 和 `matches_r0_eval_set`，但缺少 `frozen_r0_eval_set_sha256`、`matches_frozen_baseline`。需根据现有 JSON 和已冻结 SHA 证据判断能否安全补充元数据；不得改造或伪造检索指标。
