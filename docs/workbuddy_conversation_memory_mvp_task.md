## 1. 目标与现状

用户需要一个能持续服务的投研助手，而不是只能记住页面状态的单轮查询表单。
本次目标是把以下能力接入真实聊天链路，而不只是添加接口或展示历史：

1. 左侧会话列表：新建、恢复、切换、重命名、删除。
2. 会话短期记忆：继承本会话的公司、市场、年度、指标、研究需求、临时策略和待澄清问题。
3. 用户长期画像：经确认保存的偏好跨会话生效，可查看、修改、删除。
4. 上下文组装：实际回答使用适用的画像、结构化会话状态和受预算控制的历史。
5. 请求可见性：提交后立即显示用户消息和真实的处理中提示，失败也有可理解的结果。

已检查的代码现状：
- `investment_assistant/chat_session.py` 的 `messages` 为页面内状态，若干范围切换通过 `new_context()` 清空历史。
- `investment_assistant/web_app.py` 以 Streamlit 会话状态保存聊天，刷新不恢复消息；切换数据模式清空当前上下文。
- `32,000 tokens` 是历史文本估算提醒，不是模型真实上下文容量或已证明的多轮能力。
- `investment_assistant/research_memory.py` 是绑定报告、带有效期的研究注记，不是长期用户画像。
- `/api/answers` 验证研究注记编号，但当前没有把注记正文用于回答；不得把它当作已接通的记忆生成链路。
- 左侧“公司发现 / 已发布报告 / 报告任务”已移除，不得为了本任务重新加回来。
- 代码存在大量未提交改动，必须以开始实施时的实际文件为准，不能用 Git HEAD 覆盖现有成果。

## 4. 状态分层与存储

### A. 长期画像：按 tenant_id + owner_id 保存

第一版字段：称呼、关注市场/方向、研究期限、风险偏好、杠杆约束、分析与表达偏好。
每项保存：字段、值、确认状态、来源用户消息编号、更新时间、版本。
只保存用户明确提供且确认的信息；不从措辞猜测年龄、收入、资产、风险等级。
密码、令牌、账户号、身份证号等不得进入画像或摘要。
“偏保守”是用户自述的研究偏好，不得当作正式风险测评结果。

### B. 会话状态：按 conversation_id 保存

保存当前公司/市场/年度/指标、待补槽位、尚未解决的问题、本会话临时策略、数据模式、活跃证据范围。
换公司应清理不适用的公司/年度/证据状态，但保留本会话原始消息和适用的用户偏好。
不同会话绝不能共用 pending_slot、公司、年度、摘要或临时策略。

### C. 消息与摘要

保存原始用户消息、助手回复、必要的答案元数据、消息状态、序号、时间和 request_id。
摘要是可重建的派生内容，保存覆盖到的消息序号和状态版本；不是事实证据。
优先保留已确认需求、策略约束、否定条件、当前标的和未解决问题。

### 存储决策

昨天大纲的 JSON 方案是候选，不是强制设计。本任务优先使用 Python 标准库 SQLite 的单一存储，避免多个 JSON 文件之间半写入、并发覆盖和删除不一致；不引入外部数据库服务。
建议位置：`data/conversation_memory.sqlite3`，支持测试时独立临时存储，不把用户数据库提交进 Git。
会话、消息、状态、摘要、画像和确认候选应通过明确的事务边界保存；字段与文件命名可按现有规范调整。
若项目已出现等价且可靠的持久化实现，先复用并在交付回执说明，禁止重复造轮子。

## 5. 用户画像行为

- “我偏保守，主要看港股”：提取候选，先问是否保存；未确认只可用于当前会话。
- “记住我主要看港股”：仍展示拟保存内容并确认，确认对象绑定候选编号/版本，不能随便一个“是”确认别的操作。
- “查看我的偏好”：只显示本人已确认画像，不能要求输入公司和年份。
- “把我的研究期限改成三年”：展示修改前后并确认；正式替换旧值。
- “这次激进一点”：只改本会话临时偏好，不覆盖长期画像，不得覆盖用户明确的硬约束。
- “删除我的风险偏好 / 删除全部画像”：明确确认后删除，重建摘要/缓存，下一轮不得继续使用已删除偏好。
- “本次不使用长期偏好”：只停用本次画像注入，不删除长期档案。
- 新对话只清当前会话状态，保留已确认画像。

偏好优先级：本轮明确临时要求 > 本会话临时偏好 > 已确认长期偏好 > 默认值。
该优先级只适用于可覆盖偏好；碰到“不要杠杆”等约束与新要求冲突时先澄清，不能用优先级规则默默取消约束。
画像永远不是公司事实或投资适当性证明。

## 6. 短期记忆与真实回答链路

必须实现“提取本轮意图/补充项 → 合并适用会话状态 → 生成有效查询 → 调用已有受控能力 → 组织回答 → 持久化”。
不是简单再增加几条精确短语正则，不能宣称精确短语匹配等于语义理解。
如复用现有模型做意图/槽位理解，应使用可验证结构化输出；验证公司身份、期间、状态和操作范围。模型不可执行删除或直接把推断写为已确认画像。

上下文顺序：
1. 系统规则与证据边界；
2. 本用户已确认且适用的画像；
3. 当前会话结构化状态/临时约束；
4. 旧消息摘要与近期消息；
5. 本轮问题；
6. 本次受控检索/工具返回的证据（与历史记忆分区）。

近期完整对话默认以 8～12 轮作为可配置起点，但必须同时受长度预算约束；不能按固定轮数承诺不遗忘。
没有可靠的模型 tokenizer 时标注估算；32,000 仅可保留为产品提醒，不能当作模型真实额度。
优先裁剪冗余历史/旧证据，不丢当前问题、待澄清项和有效硬约束。
摘要失败时应有明确可追踪降级，不覆盖上一份有效摘要，不虚构“摘要成功”。
MVP 可用结构化状态加经过限定的提取式摘要保证关键约束，不以额外付费模型调用作为启动条件；交付时如实注明摘要类型。

真实验收重点：
- “港股 → 腾讯 → 2025年 → 收入”最终送给数据服务的查询包含正确公司、年度、指标。
- 同一公司追问“那净利润呢”继承市场/年度，不重新要求全部条件。
- “换成阿里巴巴”不能带着腾讯证据回答；不确定阿里年度时自然澄清。
- 用户风险与研究偏好必须在真实回答/澄清组织中生效，可在测试中观察实际 context/有效查询，不能只存数据库或返回 profile_ids。
- 官方与 MCP 数据分区；历史 MCP 数字不能成为后续官方回答证据。
- 恢复旧消息可供历史查看，但不能免除旧报告撤回、证据版本和可访问性复核；不得复用旧财务结论作为当前已核验回答。

## 7. 左侧 UI 与处理中反馈

保持现有海军蓝/浅灰视觉，不做全站重设计。
侧栏：新对话、最近会话列表、数据模式、简洁的“研究偏好”入口、用户身份/退出。
画像管理是小入口或对话命令，不恢复已删除的工作台和研究记忆面板。

会话列表：标题、更新时间顺序、当前高亮；支持新建/点击恢复/重命名/删除确认；列表分页或“加载更多”。
自动标题第一版可从首条有意义用户消息生成，不强依赖模型。
刷新后用会话 ID 恢复经权限校验的历史，不在 URL 保存令牌或偏好正文。
切换官方/MCP 模式不删除消息；只清不适用的活跃证据/工具状态，后续回答标明本次模式。
服务重启后数据仍可恢复；重新登录需从列表打开会话，不要求持久化登录令牌。

提交行为：
- 立即呈现用户消息，并显示“正在处理你的问题”；MCP 问题可显示“正在识别公司并查询第三方数据”。
- 只有实际进入该阶段才能显示对应进度，不伪造百分比或“正在生成”阶段。
- 超时、不可用、格式无效需有中文提示和重试入口；内部错误码放可选诊断，不替代正文。
- 按 request_id 防重复提交/重复消息，切换会话后迟到回答只归属原会话，不串到新会话。
- 处理中刷新或服务重启后，未完成请求应显示明确状态并允许重试，不无限旋转。

## 8. API、身份与删除边界

新增会话/画像 API 应复用现有 Principal 与访问控制。建议资源路径 `/api/conversations`、会话 messages、`/api/user-profile`，避免与报告注记 `/api/memories` 混淆。
客户端不得指定可信 owner_id/tenant_id；从服务端身份获取。
知道其他人的 conversation_id、message_id、pending_confirmation_id 也不能读取、修改、删除或注入。
同一 demo 凭证代表同一身份，不能宣称多个浏览器天然是不同用户；隔离测试必须用不同 actor/tenant。

删除会话：事务删除消息、状态、摘要及本会话待确认项；长期画像不随便删除。
删除画像：清除画像及相关注入缓存/派生策略；历史消息可保留展示，但不能在后续摘要/画像提取中重新激活已撤销偏好。
所有确认操作绑定用户和对象版本，过期或已替换候选不可重放。
默认不把消息/画像正文写到日志；诊断记录只保存必要标识和错误类别。
