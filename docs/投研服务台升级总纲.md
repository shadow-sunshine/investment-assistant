# 投研研究服务台升级总纲（供后续 Agent 参考）

> 日期：2026-09-24；当前状态复核：2026-09-27
> 状态：产品与工程路线图；不是已完成功能清单，也不是一次性全部实施授权。  
> 范围：仅 本仓库。不涉及 `Multi_Agent_Orchestration` 等其他项目。

## 1. 产品定位

将“一次性投研报告生成器”升级为**证据边界投研研究服务台**：用户通过聊天提出明确研究任务，查看进度、打开报告、追问指标/来源/风险/降级原因；系统在限定标的、资料和权限范围内回答，无法核实时明确说明证据不足，**不提供个性化买卖指令或保证收益**。

目标用户按小型投研团队设计；当前 Demo 已有单机多会话身份/租户边界、人工审核发布和受控记忆。它不是企业 IdP/SSO、多机事务或已验证的真实业务收益系统。

## 2. 当前事实与边界（以执行时的实时工作树复核为准）

- 报告：`investment_assistant/workflow.py` 七节点工作流；FastAPI 同步报告端点及 `report_jobs.py` 异步任务、进度、JSON 持久化。
- 受限问答：`qa.py` + `POST /api/answers`，基于指定仍有效已发布报告的结构化快照与审计来源，支持有限指标、来源页码、风险和降级问题；默认是**规则抽取**，不是通用自然语言分析或语义蕴含验证。
- 聊天入口：`chat_session.py` + `web_app.py`，明确研究指令触发任务，报告追问走问答 API；消息在 Streamlit Session State 中，刷新后不保证恢复，报告和任务可从后端找回。
- R6 身份来自服务端 `IA_AUTH_TOKENS`（actor/tenant/roles、可选过期时间）；请求者伪造 requested_by 不能改变归属。报告/任务按 tenant 隔离，记忆/关注按 tenant+owner 隔离；旧无可信归属报告不默认公有。
- 检索：Chroma 本地持久化；默认 Hash embedding，语义模型为可选且可能降级；字面分数主要用于向量候选内重排，不能称为独立 BM25 召回。已有 R0 四象限评测及 R1/R2/R3 离线实验，质量问题见 KI-006；R3 no_online_ab，不切换当前线上默认检索。
- `KNOWN_ISSUES.md` 的 KI-001 明确指出：引用编号存在不等于引用页支持具体断言。不得宣称“零幻觉”或“引用即证实”。
- 历史 `docs/审计链设计.md` 有 Phase A 实现记录，但早期未勾选事项与实际代码可能不一致；执行时以现有代码、测试、工作树为准，不用文件时间戳证明未改动。

## 3. 目标业务闭环

```text
研究请求/报告追问
  -> 意图与范围识别（ticker、报告、问题类型）
  -> 服务端身份与权限判定（目标态）
  -> 结构化指标 / 双语证据检索 / 白名单数据工具
  -> 数据源状态与新鲜度判定
  -> 候选证据页及 claim-evidence 关联
  -> 事实校验、拒答或人工审核
  -> 带证据与限制的回答/报告
  -> 任务、版本、失败原因、审核记录
```

回答类型：事实指标、来源定位、研究解释、报告生成、证据不足/数据过期/越权拒答。模型不能自行扩大资料范围或绕开服务端工具权限；回答生成与证据判定是两个不同的责任。

**R0 与 R1 的边界（2026-09-25 审阅确认）**

- **R0 不是检索优化。** R0 只是证明当前双语检索质量不足，并固化一份可复现的实验基线；它不改变线上检索路径，也不产出任何召回提升结论。
- R0 结论已登记为 `KNOWN_ISSUES.md` 的 **KI-006**（状态 `Open / R0 confirmed`）。KI-006 的根因表述是「当前检索管线的语言适配、候选召回和跨语言映射不足」，**不是**「Chroma 有缺陷」。
- R1 的第一步不是改检索结构，而是**候选池规模敏感性实验**：目标池 48 / 100 / 200，Top-K 固定 4，Hash 与 Semantic 双臂，scoped（按 ticker 限定，对齐线上）与 unscoped（跨标的污染对照）两臂，四象限分别统计，输出 Recall@4、Top-1、失败归因、耗时与候选数。只在评测器内改候选池参数。
- 若 48 → 200 的 Recall 提升明显，再考虑扩大线上候选池；若提升很小，下一步直接做**中文字面/数值锚点召回**，而不是继续调池子。
- **R1 第一步已出结果（2026-09-25）**：候选池 48 / 108 / 204 三档下，Hash 与 Semantic 两模式、四个象限的 Δ Recall@4 与 Δ Top-1 **全部为 0.0000**，失败归因分布逐项不变（见 `data/evaluations/candidate_pool_sensitivity.md`）。判定：**暂不扩大线上默认候选池**，下一步验证中文字面/数值锚点召回。R1 结构性改动（独立字面召回、融合、页面重排）仍为待做。
- **该结论不得泛化**：只成立于「32 条冻结样本 + 4 份冻结资料（sha256 全部 match）+ Hash / Semantic 两种 embedding + `RAG_RERANKER_MODE=disabled` 的默认路径」。Cross-Encoder 分支（启用时候选池固定为 30）未单独实验；不得外推为所有资料、所有 reranker 配置或生产环境查询都不受候选池影响。

多 Agent、MCP、模型微调、复杂长期记忆不是前置目标；只有在工具、权限、评测与审计边界稳定且业务问题确实需要时再论证。

## 5. R0 任务卡（已完成首版，保留供复跑对照）

> 状态：R0 已完成首版，结果见 `data/evaluations/bilingual_r0.md`。本节保留原始边界，供复跑时对照，不作为待办。R1 首张任务卡见第 4 节阶段 3。

**目标**：先弄清当前检索在哪些语言和证据类型上失败，而不是直接换数据库或模型。

- 建立四象限样本：中文问中文、英文问英文、中文问英文、英文问中文。覆盖 AAPL、MSFT、600519.SS、0700.HK 等现有本地资料；先检查资料是否足以构造真实 gold page。每条记录问题、ticker、资料版本、目标页/证据片段、语言和不可接受的跨标的来源。
- 将现有 Apple 评测作为历史基线，新增**独立**样本，不能为提高指标而改 gold page、删除失败题或在看过结果后反向编造标注。
- 在相同资料快照和 Top-K 条件下分别测试 Hash、当前可用的 Semantic；若模型离线不可用，记录明确原因，不把 Hash fallback 冒称 Semantic 成绩。
- 报告按四象限拆分 Page Recall@4、Top-1 相关性、关键词/数值核验、错误 ticker 来源数；列出失败样本及原因（切块、术语、模型、候选召回、排序、OCR/原始资料）。小样本结果只作为实验基线，不外推为业务准确率。
- 此阶段不改变报告生成的默认检索路径。交付可复跑命令、样本与结果、下一步最小改进假设；若缺标注或语义模型，明确阻塞而不是伪造结果。

## 6. 通用工程与验收约束

- 后续每期先确认现有未提交改动，保留 `rag.py`、`llm_generation.py`、`safety.py`、`workflow.py` 和黄金回归既有行为；需要改冻结区时单独提出变更依据、对照评测和用户确认，不以新抽象绕过安全门禁。
- 不把 `requested_by` 或 ticker 参数当成授权；新增外部工具前先定义服务端白名单、输入/输出 Schema、超时、错误类型、数据权限与审计字段。
- 对用户可见的结果区分 `answered`、`insufficient_evidence`、`out_of_scope`、`source_unavailable`、`needs_review` 等状态；缺证据不得填充为确定结论。
- 测试包括离线单元/API、异常和边界、原黄金回归；前端改动还要检查窄屏、桌面和主交互。真实网络、真实数据源、浏览器 E2E 与离线桩测试分别报告。
- 不使用计划中的目标值冒充已取得的成果。量化指标只有在样本、基线、命令、日期和结果可追溯时才写入简历；如“人工时间下降”“准确率提升”必须有对照实验。
- 每期汇报：改动文件、已运行验证、未验证路径、失败用例、风险与下一步；未经授权不提交、推送或修改其他项目。
