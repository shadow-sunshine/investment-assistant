- R5 的 `supported` 仅指当前证据锚点的确定性/结构核验，不表示 claim 文本语义蕴含；单条 fixture 通过不覆盖整份报告。没有完整 coverage/人工审核时整份报告 `needs_review`、正文不可从报告 API 交付；生成 `completed` 不等于审核或发布。
- 来源原文核验必须绑定同 ticker/report/source_id/file/page、报告生成时 SHA、可信 manifest 实际字节与同页片段。只有 citation 或审计 JSON 自带片段不构成原始资料证明；缺元数据/版本/可读原文时 fail-closed。

## R6/R7 接管实施决策（2026-09-27）

- WorkBuddy 费用耗尽中断；用户授权主助手直接完成当前 R6/R7 批次。未继续派发 WorkBuddy，未扩展到 R8、生产身份服务或检索切流。
- 单机真实认证采用服务端环境变量 `IA_AUTH_TOKENS` 映射 actor/tenant/roles；可选 `expires_at` 必须带时区，缺配置/错误配置/无效/过期均拒绝。这不是生产 IdP 或密钥管理。旧报告没有可信归属时隔离，admin 只能查看迁移状态，不能绕过审核发布。
- 生成完成与发布严格分离。新建报告的归属由服务端绑定；报告 ID 加随机后缀并排他创建，避免同秒跨租户覆盖。生成/取消/来源健康的角色边界在 API 服务端执行。
- 在冻结工作流外增加人工 claim 登记，不增加自动抽取或修改生成器。保存 claim 集使审计 JSON 字节变化，所有旧审核/发布失效；审核必须逐条确认与整篇覆盖声明，批准是人工责任记录，不是算法自动证明语义蕴含。
- 创建、审核、发布三个人员分离。每次发布/读取重新核验 MD/JSON/claim 集/tenant/report_id/白名单资料实际字节。后续拒审作废旧批准，撤回后的重新发布必须重新审核；不能重放旧批准。
- JSON 状态使用进程内锁、临时文件、flush/fsync 与 replace；受保护版本动作使用单进程事务锁。支持单服务、单 worker；不声明多进程/多机事务、外部审计不可篡改或恶意本地管理员防护。
- 审计分 intent / allow / deny；意图记录失败不执行受保护写操作。日志不记录 token、正文、问题或记忆内容，只记录主体、路由类别、目标路径摘要、时间、结果/错误码与版本。
- R7 仅显式触发固定白名单文件/已发布报告版本检查，不做自动联网监控或动态发现所有新文件。相同状态重复检查复用已持久化 diff/时间以保证结果幂等；报告/证据失效或缺失只标待审/不可用，不生成投资结论变化。
- 研究记忆为 owner 私有、1–90 天、可撤销且绑定审核/发布版本的用户注记。自由文本不能成为事实证据，也不注入生成器；问答可校验 memory_ids 的有效性，返回明确的 user_note_not_factual_evidence 元数据。过期/撤回/漂移后不返回记忆正文或注入回答。
- 浏览器烟测使用隔离临时目录、合成 OFFLINE FIXTURE 和三个角色，不调用真实研究网络，不将合成验证写成真实业务质量成绩。界面保留原海军蓝风格，凭证只存单个 Streamlit 会话；退出/身份变化清空全部会话状态，每次重绘复验发布状态，失效前先移除旧正文/回答。
